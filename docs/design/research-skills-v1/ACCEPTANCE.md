# 两个 Skill 的实施验收设计

状态：验收方案，尚未执行。旧有插件验收见 `docs/evidence-reader-acceptance.md`，不能作为两个新 Skill 的验收结果。

## 1. 数据与对照

建立独立验收 scope，选用用户真实库内中文/英文、单栏/多栏、正文/表格、跨页、重复文本与缺附件样本。扫描/旋转件作为扩展或明确拒绝精确定位的样本。

研究质量样本另准备至少10篇真实论文、20项实验记录、30个atom，其中至少5个反证/限定场景、5个无法支撑的句子、5个方法或原创假设场景。由人工核对原文建立参考标注，记录分歧；样本和阈值须在正式验收前冻结，不能用模型自评分冒充准确率。

数字目标是第一版门槛，达不到就记录失败并修复；小样本通过不代表全领域性能保证。

## 2. 场景与通过标准

| 场景 | 可观察结果 | 通过标准 |
| --- | --- | --- |
| 工具能力与scope | 状态/参数/版本清单；不存在scope的调用 | 不存在工具不调用；scope错误拒绝，不读取其他项目 |
| 本地充分 | 本地阅读账本与外部调用记录 | 不为凑篇数补库；实际已读部分与报告一致 |
| 本地不足 | 缺口→外部查询→候选→导入→附件→索引→再阅读 | 每一步有状态；授权内分批导入；缺全文不算实验已读 |
| 来源重复/版本 | 同一论文跨源、预印本/正式版 | 无重复入库；同实验不重复计独立证据；引用版本明确 |
| 中英文/未标记论文 | 已知相关论文的召回 | 不能因无标签或译名不同漏掉所有结果；记录各查询来源 |
| 大量阅读与恢复 | 默认规模任务中断后续跑 | 不重复创建条目/实验/卡；账本计数一致；超限显式标partial |
| 选题来源 | 每个方向改进点到具体实验链 | 全部核心来源可追到论文版本、实验、原文段或表图锚点；零虚构数值 |
| 实验可比性 | 同指标但不同数据划分/硬件的干扰样本 | 不生成误导排序或无条件“提升%”；缺种子/误差留空 |
| 最近邻与创新边界 | 已有近似工作和新方向 | 呈现差异与检索限制，不宣称绝对首创 |
| 原子拆分 | 含多个结果、因果、泛化和方法步骤的输入 | 参考标注中的独立需求召回≥90%；各atom能独立判定；不把假设当事实 |
| 关系核验 | 正/反/限定/不足、否定句干扰 | 人工标注上关系宏平均F1≥0.85；不足/假设误标支持为0；所有分歧附原文 |
| 证据原文 | paraphrase、错误数字、伪造句 | 全部拒绝逐字核验；正式交付卡的完整quote均可回验 |
| 出处 | 正确页、错附件、重复句、更新PDF | 正确来源精确定位；错附件/哈希变化/未消歧不得高亮；页index与label不混用 |
| 表图 | 表格数值/脚注、视觉估读 | 已核验值逐项人工比对无错；不可靠样本显式待核验，不能冒充正文引语 |
| 双端打开 | 工作台和Zotero面板点击 | 两端对同card打开同附件同span；有实际渲染/批注回执；仅排队不能显示成功 |
| 跨页与离线 | 多span及Zotero离线/超时/重投 | 各span正确；离线失败可见；重投不重复批注；无假成功 |
| 反向建卡回绑 | Reader手工划选、选atom、重开原文 | 保存原始选区；绑定正确；空atom入待整理；相同request幂等；错坐标拒绝 |
| 清理与笔记 | 临时批注与普通用户批注共存 | 仅清理桥接所属临时批注；普通批注保留；笔记重复提交更新不重复 |
| 实时模型 | 两会话、快速切换、切换后立即提交 | 新任务使用最新已确认revision；旧任务保留快照；无跨会话误用；日志不含密钥 |
| 旧卡迁移 | 旧v2/失效定位卡 | ID保留；未复核不标正式可用；已有插件正向/反向流程回归通过 |

正式引文的三层核验通过率要求100%是过滤门槛：不合格项保留为缺口，不允许靠排除困难样本声称全任务100%已支持。报告同时公布 atom 总数、可支持数、未解决数与人工审查样本数。

## 3. 最小纵向演示

1. 给一个真实主题，检索本地两篇以上原始研究，补一项已识别缺口，生成阅读账本和实验矩阵。
2. 形成一个带具体实验来源的方向与大纲，再给出3个atom：一个支持、一个限定/反驳、一个待验证假设。
3. 展示原文、语义、定位三类状态；在工作台点击支持卡，观察真实Zotero目标页与高亮。
4. 在Zotero真实鼠标选文，点击“存为证据卡”，选择已有atom；返回工作台查看绑定，再次打开并高亮。
5. 改动目标句或更新测试PDF，确认旧绑定/坐标被标记失效；切换模型后立即启动下一任务，核对revision。

## 4. 交付证据与结果表述

每个场景记录输入、run/scope/revision、job/model_revision、atom/card/action ID、预期/实际结果及失败原因。输出JSON结果、阅读账本、实验/句子CSV和必要的Reader截图。

协议派发、程序选区测试、真实手工划选、页面状态确认和像素检查分别记载；不得互相冒充。真实PDF、账号、密钥和完整文库不提交Git。

通过后才将两个Skill复制到发现目录并做真实提示语触发检查；未通过则保留草案和具体失败项。最终报告说明已完成范围、未覆盖文献类型、剩余缺口与回滚方式。

## 5. v1.1 新增的独立使用、顺序与上层二审验收

| 输入或操作 | 预期结果 |
| --- | --- |
| 只请求选题；只提供自拟大纲请求找证据 | 前者交付方向后结束；后者无父 run、无 handoff 也完成拆句、检索、二审和导出 |
| 要求联合运行，先产出多个方向，再指定其中一个 | 事件时间线显示 Skill 1 完成后启动 Skill 2；子 run 只含选中方向，可追溯父版本 |
| 下层高分支持，材料实际为仿真延迟，目标为真机能耗 | 上层提交具体条件和指标错配；错误绑定驳回；在引用、导出、覆盖统计中均无正面支持 |
| 下层初判错误，另有直接反证；同一段匹配两个不同 atom | 每个 binding 各存一份上层意见并链接原段。实质冲突未解决时 atom 标 disputed，不列为已完整支持 |
| 只运行 PaperQA2 或人工标记、尚无上层意见 | 上层仍显示待审。两层使用同一模型名称也须有两个独立阶段的记录 |
| 表格脚注缺失、分页中断、再次提交 | 缺脚注退回补取，中断保留未审列表，重试不重复入账。审完全部候选才出完整汇总 |
| 二审后改 atom、替换附件、增加反证 | 旧包提交被拒绝；相关审核或汇总失效；恢复前各正式入口拒绝过期结论 |
| 对冻结人工标注集分别统计初判与二审 | 保留两层混淆矩阵、纠正/引入错误数及分歧案例。既有关系质量门槛用于二审结果，分别报告下层质量与待审数量 |
