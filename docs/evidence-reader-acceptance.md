## 本轮发现并修复的问题

1. **反向建卡丢失真实选区**：旧代码只传文本与猜测页码。现在保留 Reader 的 `position`（含跨页坐标字段）、`pageLabel`、`sortIndex`，核对附件归属、完整原文、物理页和矩形位置；缺失或不一致时拒绝保存。
2. **反向摘录误归到最近的研究范围**：未指定范围的手工摘录改为归入专门的“Zotero 阅读器摘录”，不再默认污染最近课题。论点可在选文弹窗输入；留空明确标记待整理，相关性分数不再虚构为 8.5。
3. **打开成功回执过早**：等待阅读器初始化、目标物理页真正渲染、批注在阅读器模型中存在，再返回包含附件、页码、批注键和渲染状态的回执。阅读器返回 `undefined` 的延迟加载场景同样等待实际实例。
4. **Zotero 跨环境对象错误**：传入内容阅读器的对象必须按其规则复制；把字符数组带回插件环境后再处理，防止回调向低权限环境返回插件对象时报权限错误。修正 `Reader.setAnnotations` 的参数类型为真实 `Zotero.Item`。
5. **批注排序与刷新**：使用运行中阅读器的原生排序元数据；已有卡片批注更新坐标并主动刷新，避免旧错误坐标被反复复用。轮询互斥，未知动作不再返回成功。
6. **插件版本登记与本地化打包**：打包包含真实 ZIP 目录条目，供 Zotero 枚举 FTL 文件；通过 AddonManager 正式校正登记版本。替换原先缺文件、硬编码旧版本并强改 `extensions.json` 的安装脚本；现在保留备份，不伪造扩展记录。
7. **系统外部链接不跳转**：实测 `zotero %u` 的桌面入口打开应用却不处理目标链接，直接 `zotero -url ...` 正常。已备份并把用户桌面入口改为显式 `-url %u`，刷新桌面关联，系统入口复测通过。可复现修复脚本：`scripts/repair_zotero_scheme.py`。

## 验收方法与边界

- 本轮不是用后台 POST 请求冒充阅读器建卡：测试在真实 Zotero Reader 的 PDF 字符层建立程序选区，等待原生选文弹窗实际生成按钮，然后点击同一按钮。服务器记录了 Reader 的选区元数据、新卡与出处验证结果。
- 页面证据来自 PDF 阅读器的当前页、页面渲染完成状态、批注载入及选中状态，并与已保存的 Zotero 批注及真实 PDF 坐标对应。本轮没有获取像素截图或执行人工鼠标拖选，不能把它表述为人工肉眼验收。
- 跨页正向高亮已实测；中英文单页反向建卡已实测。跨页反向选文、扫描件 OCR、旋转页和其他 Zotero 版本仍需单独验收。
- 验收卡的论点为测试时人工给定，不是模型抽取质量评估；本轮不声称已经验证所有原子论点的语义正确性。
- Python 完整回归 **49 项通过**；Reader 桥接契约测试通过（延迟初始化、目标页确认、批注刷新、错误页拒绝）；JavaScript 语法及变更格式检查通过。
